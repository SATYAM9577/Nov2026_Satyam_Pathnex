
Day 10 — Advanced Kubernetes, Jenkins, and GitLab CI/CD

1. ANSIBLE — Create Docker Containers for Multiple Applications

- name: Setup Docker Containers for Multiple Apps
  hosts: all
  become: yes
  tasks:
    - name: Pull Web App Image
      docker_image:
        name: my-web-app
        source: pull

    - name: Pull Database App Image
      docker_image:
        name: my-database-app
        source: pull

    - name: Run Web App Container
      docker_container:
        name: web-app
        image: my-web-app
        state: started
        published_ports:
          - "8080:80"

    - name: Run Database App Container
      docker_container:
        name: database-app
        image: my-database-app
        state: started
        published_ports:
          - "3306:3306"

Note:
- Ansible automates multiple container deployments.
- docker_image pulls images from a container registry.
- docker_container creates and manages containers.
- Port 8080 maps to the web application's port 80.
- Port 3306 maps to the database's port 3306.
- Docker Engine and the required Ansible collection must be installed.
- Database credentials should be managed securely.


2. TERRAFORM — VPC with Public and Private Subnets

resource "aws_vpc" "main" {
  cidr_block = "10.0.0.0/16"

  tags = {
    Name = "Pathnex-VPC"
  }
}

resource "aws_subnet" "public" {
  vpc_id                  = aws_vpc.main.id
  cidr_block              = "10.0.1.0/24"
  availability_zone       = "us-east-1a"
  map_public_ip_on_launch = true

  tags = {
    Name = "Pathnex-Public-Subnet"
  }
}

resource "aws_subnet" "private" {
  vpc_id            = aws_vpc.main.id
  cidr_block        = "10.0.2.0/24"
  availability_zone = "us-east-1b"

  tags = {
    Name = "Pathnex-Private-Subnet"
  }
}

Note:
- VPC provides an isolated virtual network in AWS.
- Public subnet is intended for resources requiring internet access.
- Private subnet is intended for resources that should not be directly reachable from the internet.
- map_public_ip_on_launch assigns public IP addresses to instances launched in the public subnet.
- A public subnet also requires an Internet Gateway and a route table with a route to it.
- A private subnet may use a NAT Gateway for outbound internet access.
- Replace availability zones according to your AWS region.


3. KUBERNETES — Deploying StatefulSet

Headless Service:

apiVersion: v1
kind: Service
metadata:
  name: pathnex-db
spec:
  clusterIP: None
  selector:
    app: pathnex-db
  ports:
    - port: 3306
      name: mysql

---

StatefulSet:

apiVersion: apps/v1
kind: StatefulSet
metadata:
  name: pathnex-db
spec:
  serviceName: pathnex-db
  replicas: 3
  selector:
    matchLabels:
      app: pathnex-db
  template:
    metadata:
      labels:
        app: pathnex-db
    spec:
      containers:
        - name: db
          image: mysql:5.7
          ports:
            - containerPort: 3306
          env:
            - name: MYSQL_ROOT_PASSWORD
              valueFrom:
                secretKeyRef:
                  name: mysql-secret
                  key: root-password
          volumeMounts:
            - mountPath: /var/lib/mysql
              name: mysql-storage

  volumeClaimTemplates:
    - metadata:
        name: mysql-storage
      spec:
        accessModes:
          - ReadWriteOnce
        resources:
          requests:
            storage: 1Gi

Note:
- StatefulSet manages stateful applications.
- Each Pod receives a stable identity and persistent storage.
- Headless Service provides stable network identities.
- volumeClaimTemplates creates a separate PVC for each Pod.
- Create the mysql-secret before deploying this StatefulSet.
- A suitable StorageClass and persistent volume provisioning must be available.


4. JENKINSFILE — Build and Deploy to Kubernetes

pipeline {
    agent any

    environment {
        IMAGE_NAME = 'pathnex-web-app'
    }

    stages {
        stage('Build Docker Image') {
            steps {
                script {
                    docker.build("${env.IMAGE_NAME}")
                }
            }
        }

        stage('Push Docker Image') {
            steps {
                script {
                    docker.withRegistry(
                        'https://registry-1.docker.io',
                        'docker-credentials'
                    ) {
                        docker.image("${env.IMAGE_NAME}").push('latest')
                    }
                }
            }
        }

        stage('Deploy to Kubernetes') {
            steps {
                script {
                    sh 'kubectl apply -f deployment.yaml'
                }
            }
        }
    }
}

Note:
- Build stage creates the Docker image.
- Push stage uploads the image to Docker Hub.
- Deploy stage applies the Kubernetes manifest.
- Jenkins requires Docker, kubectl and valid registry and cluster credentials.
- Use the correct Docker Hub namespace and image tag in a real deployment.


5. GITLAB CI/CD — Build, Push and Deploy

stages:
  - build
  - push
  - deploy

variables:
  IMAGE_NAME: "$CI_REGISTRY_IMAGE:$CI_COMMIT_SHORT_SHA"

build:
  stage: build
  script:
    - docker build -t "$IMAGE_NAME" .

push:
  stage: push
  script:
    - echo "$CI_REGISTRY_PASSWORD" | docker login "$CI_REGISTRY" -u "$CI_REGISTRY_USER" --password-stdin
    - docker push "$IMAGE_NAME"

deploy:
  stage: deploy
  script:
    - kubectl apply -f kubernetes/deployment.yaml

Note:
- Build stage creates the Docker image.
- Push stage uploads the image to GitLab Container Registry.
- Deploy stage applies the Kubernetes configuration.
- GitLab runner requires Docker-compatible execution and kubectl access.
- Kubernetes deployment should reference the same image tag that was pushed.


6. DOCKER — Working Directory and COPY

Dockerfile:

FROM ubuntu:22.04

WORKDIR /opt/pathnex/devops-project

COPY . /opt/pathnex/devops-project/

CMD ["ls", "-l", "/opt/pathnex/devops-project"]

Real Path:

/opt/pathnex/devops-project

Note:
- FROM specifies the base image.
- WORKDIR sets the working directory inside the container.
- COPY copies files from the build context into the image.
- CMD defines the default command executed when the container starts.
