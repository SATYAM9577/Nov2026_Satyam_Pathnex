Day 08 — Introduction to Docker and CI/CD Pipelines

1. ANSIBLE — Install Docker Compose

- name: Install Docker Compose
  hosts: all
  become: yes
  tasks:
    - name: Install dependencies
      yum:
        name: python3-pip
        state: present

    - name: Install docker-compose
      pip:
        name: docker-compose
        state: present

Note:
- Ansible installs Python pip and Docker Compose.
- Docker Engine must be installed separately.


2. TERRAFORM — EC2 with Security Group and EBS Volume

resource "aws_security_group" "allow_ssh_http" {
  name        = "allow_ssh_http"
  description = "Allow SSH and HTTP access"

  ingress {
    from_port   = 22
    to_port     = 22
    protocol    = "tcp"
    cidr_blocks = ["0.0.0.0/0"]
  }

  ingress {
    from_port   = 80
    to_port     = 80
    protocol    = "tcp"
    cidr_blocks = ["0.0.0.0/0"]
  }

  egress {
    from_port   = 0
    to_port     = 0
    protocol    = "-1"
    cidr_blocks = ["0.0.0.0/0"]
  }
}

resource "aws_instance" "pathnex_ec2" {
  ami           = "ami-0abcd1234abcd1234"
  instance_type = "t3.medium"

  vpc_security_group_ids = [
    aws_security_group.allow_ssh_http.id
  ]

  root_block_device {
    volume_size = 30
    volume_type = "gp3"
  }

  tags = {
    Name = "Pathnex-EC2"
  }
}

Note:
- Security Group controls inbound and outbound traffic.
- Port 22 is used for SSH.
- Port 80 is used for HTTP.
- EBS provides persistent block storage.
- Replace the example AMI ID with a valid regional AMI.


3. KUBERNETES — Service with NodePort

apiVersion: v1
kind: Service
metadata:
  name: pathnex-service
spec:
  type: NodePort
  selector:
    app: pathnex-app
  ports:
    - protocol: TCP
      port: 80
      targetPort: 80
      nodePort: 30007

Note:
- NodePort exposes an application through a port on each cluster node.
- Default NodePort range is 30000–32767.
- The selector connects the Service to matching Pods.


4. JENKINSFILE — Docker Build and Push

pipeline {
    agent any

    stages {
        stage('Build Docker Image') {
            steps {
                script {
                    docker.build('pathnex-app')
                }
            }
        }

        stage('Push Docker Image') {
            steps {
                script {
                    docker.withRegistry(
                        'https://registry.hub.docker.com',
                        'docker-credentials'
                    ) {
                        docker.image('pathnex-app').push('latest')
                    }
                }
            }
        }
    }
}

Note:
- Build stage creates a Docker image.
- Push stage uploads the image to a registry.
- docker-credentials represents the Jenkins credentials ID.
- A properly tagged image with your Docker Hub namespace is required for an actual push.


5. GITLAB CI/CD — Build and Push Docker Image

stages:
  - build
  - push

build:
  stage: build
  script:
    - docker build -t "$CI_REGISTRY_IMAGE:$CI_COMMIT_SHORT_SHA" .

push:
  stage: push
  script:
    - echo "$CI_REGISTRY_PASSWORD" | docker login "$CI_REGISTRY" -u "$CI_REGISTRY_USER" --password-stdin
    - docker push "$CI_REGISTRY_IMAGE:$CI_COMMIT_SHORT_SHA"

Note:
- Build stage creates the Docker image.
- Push stage authenticates and uploads the image.
- GitLab predefined variables provide registry credentials and image location.
- A Docker-compatible runner is required.


6. DOCKER — Alpine Linux Application

Dockerfile:

FROM alpine:latest

WORKDIR /opt/pathnex/alpine-app

CMD ["echo", "Hello Pathnex"]

Note:
- Alpine Linux is a lightweight Linux distribution.
- WORKDIR sets the working directory inside the container.
- CMD specifies the default command executed when the container starts.
